# SSHub 首版实施计划

状态：2026-11-16 整体方案已确认，P1–P3 已完成阶段验证，P4–P6 尚未开始。结果见 [P1](issues/01-connection-library.md)、[P2](issues/03-secure-ssh.md) 和 [P3](issues/04-workspace.md)，其中列明实测范围与兼容性限制。P3 后已按反馈完成[界面简化](issues/05-simplify-interface.md)，中间只保留标签与终端，并完成[内置标题栏](issues/06-custom-titlebar.md)。

## 开发原则

采用最小可使用阶段逐步交付；每阶段验证真实用户行为、公共边界与错误路径，默认 test-after。继续固定 MyGo 版本，协议与凭据处理不放进 UI。

按用户要求只保留正式项目代码，已移除性能原型和专用脚本。历史性能记录仅用于选型参考；后续对正式产品建立性能采样与负载验证。

按仓库约定创建 `issues/NN-slug.md`，标明状态、类型、阻塞关系及验收标准；不提前将未实现阶段标记完成。

## 阶段交付

| 阶段 | 可使用的交付结果 | 主要验收 |
| --- | --- | --- |
| P1：应用骨架与连接库 | 三栏布局、右侧内嵌传输区域、配置增删改查、分组、收藏、搜索与最近使用 | 保存后重启仍存在；100 条配置可查找；坏配置不被静默覆盖；启动不等待网络 |
| P2：单终端安全连接 | 异步连接、密码与私钥认证、加密私钥、Windows Agent、单层跳板、主机信任、凭据库 | 成功与失败认证、取消连接、未知及变化主机密钥、跳板和目标分别验证；真实终端收发与 resize |
| P3：多会话工作区 | 标签组、水平与垂直分屏、焦点联动、终端搜索与缩放、断线重连、布局恢复 | 同配置多会话互不误关；最多四可见窗格及八会话；断线输出保留；恢复后不自动连；退出清理资源 |
| P4：SFTP 文件与传输 | 浏览和基础管理、文件夹传输、拖入上传、属性权限、全局任务队列 | 切换服务器不中断传输；覆盖与删除确认；无权限、断网、取消和重试；未完成文件不误报成功 |
| P5：设置与迁移 | 浅深主题与跟随系统、字体设置、导入导出、信任记录管理 | 主题与布局持久化；导出不含秘密；迁移后重新指定凭据；导入重名与损坏文件处理 |

## 关键场景验收

### 连接与安全

- 从空连接库新建服务器，明确校验字段，连接过程不冻结 UI。
- 未知主机需人工确认；密钥变化时拒绝连接；取消确认不会留下已信任记录。
- 认证失败、私钥不可读、口令错误、Agent 不可用及跳板失败可定位并重试。
- 默认不保存密码与口令；勾选记住后可重新使用；系统凭据库不可用时不得回退明文落盘。
- 主机与凭据测试优先使用本地临时 SSH / SFTP 服务和临时密钥，不操作真实服务器数据。

### 终端与生命周期

- 同一配置打开两个独立会话；切换窗格后文件面板准确跟随。
- 验证 UTF-8、中文输入法、复制粘贴、交互式程序、终端 resize 及不同尺寸下的可用性；实际兼容性以测试结果记录。
- 模拟断网后，已有输出可读；重连建立新会话；应用重启只恢复布局和标签。
- 关闭会话、取消连接、退出与重连后不遗留无归属的连接、后台任务或本地子进程；经确认继续的传输任务保持明确归属，直到完成或取消。

### 文件与传输

- 验证空目录、大目录、中文及含空格路径、文件夹递归传输和无权限目录。
- 符号链接不被当作普通目录盲目递归，尤其不允许删除越过链接边界。
- 覆盖选择可应用到本批次；取消、连接中断或磁盘空间不足后任务与目标文件状态准确。
- 任务绑定创建时的服务器与目标路径，不因焦点切换而上传或删除到另一台服务器。
- 拒绝将失败或取消显示为成功；重试从单文件起点执行。

### 配置、性能与发行

- 配置增删改查、导入与布局保存采用可靠写入方式；读取或写入失败能恢复或保留原数据。
- 检查导出文件不含密码、口令和私钥内容；日志和错误信息不输出秘密。
- 同一机器、同一负载定义下比较原型基线与产品版本；记录完整构建与运行环境。
- 正式验收缓存启动、单终端空闲、八终端十分钟负载及真实窗口交互；另报冷启动、网络握手及测量局限。
- 在不依赖开发工具链的运行环境检查 ZIP 内容、DLL 加载、用户数据目录和更新后配置读取。

## 验证命令与结果记录

Go 代码变更执行 `gofmt`、`go test ./...` 与 `go vet ./...`。UI 变更使用真实窗口或 MyGo 官方 automation；发行与性能使用正式构建，产品性能采样工具随后续阶段接入。

验证结果随实现任务记录；未执行或无法可靠自动化的项目明确标注，不以现有原型通过的测试替代新增行为验收。

## 已知工程关注点

- MyGo 为较新的框架；固定版本，升级前验证终端、分屏、主题、自动化与内存表现。
- Windows Agent、系统凭据库、中文输入法及动态库打包需要 Windows 实测，不能仅依据接口存在认定可用。
- 终端输出缓冲、目录列表与传输队列应有资源边界，避免长期运行增长；具体容量在实现时按性能测试确定并记录。
- 传输与终端的关闭关系、连接配置修改对活动连接的影响，按规格中的已确认收尾约定落实。
