# 日志高亮需求地图

## Notes

- 2026-11-17：用户经常在终端使用 `tail` 查看滚动日志，希望可配置 `info`、`error` 等关键字、日期及 JSON 的高亮，并询问当前输出行数限制。
- 使用 grilling 逐轮澄清，结合 domain-modeling 记录已确认概念；Q22 确认操作形态，随后用户取消专门 JSON 高亮；当前行为以[最终规格](spec.md)为准，04 历史缓冲设置已实现，高亮功能仍在推进。
- 代码事实：[`session.go`](../../../internal/desktop/session.go) 在连接开始时捕获配置的历史缓冲预算，默认约 2 MiB，可在设置中选 2／8／32／64 MiB；这是历史回滚预算，不是日志行数。未设置累计输出行数截止，旧历史随缓冲淘汰。
- 依赖事实：固定的 MyGo v0.9.1 公开终端接口没有自定义多规则／语法高亮入口；内部有搜索结果的显示层着色。现有单文本搜索会改变选中位置，不能直接充当多规则日志高亮。
- 技术调查：扩展终端显示层可在 Ghostty 解析后着色并保留原始文本，但用户在 Q14 拒绝维护依赖补丁，此路线不采用。直接向 SSH 输出注入 ANSI 需要处理已有颜色、分块、控制序列、覆盖写入与全屏程序等问题，不宜视为简单字符串替换。
- 接入约束：MyGo 终端插件属于根模块，不能单独用模块替换；公开的全量文本／快照接口不足以可靠映射可见单元格。原插件内部具备行文本、软折行及单元格信息，适合在绘制阶段扩展；固定版本源码补丁的接入方式仍须原型验证，不升级 MyGo 或 Ghostty。
- 历史显示可按需着色，无需为高亮再保留一份完整日志；软折行的逻辑行开头可能位于视口之外，需验证回溯边界及历史开头已被淘汰的情况。
- 性能证据仅限[历史 P6 报告](../../performance/20261116-product.md)：八会话各约 1,000 条逻辑行／秒，持续约十分钟；计量为接收数据，不代表最高渲染吞吐，也不是当前版本或新增高亮后的复测。
- 输入事实：[`ssh.go`](../../../internal/connection/ssh.go) 的 `Shell.Write` 承载发往远端的终端输入，可以在本地观察，无需 xterm.js 或修改 MyGo。这里得到的是按键／粘贴／控制序列流，不是 shell 最终执行的命令；方向键历史、补全、别名、应用内输入及命令结束使本地命令判断存在歧义。此前关于可靠命令身份的限制不代表无法获取输入。

## Decisions-so-far

- Q1（开关方式由 Q16 取代）：保留现有终端，不另建日志阅读页面。
- Q2（由后续范围调整取代）：原要求 JSON 按语法类别着色，现已取消专门 JSON 功能。
- Q3（JSON 预设由后续范围调整取消）：内置日志级别、常见日期预设；允许新增普通关键字／正则规则、修改颜色和逐条开关；首版不增加脚本或插件。
- Q4（开关方式由 Q16 取代）：所有终端共用一套保存的规则；首版不增加连接专属规则或命名规则组。
- Q5：服务器已有的显式 ANSI 前景色优先，仅为使用默认前景色的文本补充高亮。
- Q6（由 Q16 取代）：原先要求历史重染及关闭恢复颜色，现已放弃。
- Q7（由后续范围调整取代）：不再单独定义 JSON 行与语法解析边界，按普通文本规则处理。
- Q8：提供 2／8／32／64 MiB 历史缓冲档位，默认保留 2 MiB；不承诺固定日志行数或等量进程内存。
- Q9：内置日志级别按完整单词匹配且忽略大小写；自定义普通关键字按片段匹配，可切换大小写敏感；正则采用 Go 语法，保存前提示无效表达式。
- Q10（JSON 层级由后续范围调整取消）：自定义规则按列表从上到下优先，其次日志级别、日期；服务器已有显式颜色优先，保留搜索及选择的可辨识性。
- Q11（开关方式及生命周期由 Q16 取代）：规则在设置中编辑；备用屏幕暂停高亮的目标保留，识别范围待验证。
- Q12：缓冲档位仅对新建或重连终端生效，现有终端不变。
- Q13：超长行或处理超出预算时允许跳过相应高亮并提示，只降级颜色，不丢弃或修改文本；具体预算待验证。
- Q14：不接受维护 MyGo 依赖补丁，重新选择方案；未授权开始依赖补丁原型。
- Q15 回复：用户尚未选择独立日志视图，询问其含义；表示可以放弃历史重染，或将开关改为设置中统一控制、不放右键菜单。新的开关范围和生命周期待确认，不能直接视为已选择其中一种完整方案。
- Q16（统一开关及其持久化由 Q22 取代）：由 SSHub 本地给新增输出着色，无需修改 MyGo 或安装远端工具；开启前的文本不补色，规则变化及关闭不改变已有历史颜色。
- Q17：提示符及时显示优先；以最多约 20 ms 额外等待为原型目标，允许跨已显示边界的关键词／正则漏色，文字必须完整保留；时间目标尚未验证。
- Q18 回复（自动限定命令的要求由 Q22 取代）：用户希望仅在 `tail` 等滚动日志命令下高亮，不在 vim、opencode 等命令下高亮；目前主要使用 `tail`。
- Q19（JSON 分类由后续范围调整取消）：预设级别 TRACE、DEBUG、INFO、WARN／WARNING、ERROR、FATAL／PANIC；日期覆盖常见 YYYY-MM-DD、YYYY/MM/DD、时间及 ISO 8601 组合。内置配色适配浅深主题，自定义规则首版选定单一颜色；主题切换仅影响后续输出，其他格式可用自定义规则补充。
- Q20 回复：用户希望沿用终端输入识别，询问能否像之前 xterm.js 应用一样获取发给终端的内容；未选择应用发起日志标签或远端 shell 集成。已核实本项目可以观察输入，待确认是否接受本地推测的识别边界。
- Q21 回复：未选择命令推测，转而询问手动右键开关是否可以省去命令识别；已说明可以，但开启期间其他程序的输出也可能着色。
- Q22（最终确认）：规则全局共用，右键开关只控制当前终端，默认关闭；只着色新增输出，历史颜色保留。用户手动决定看日志时开启、离开时关闭；不增加命令识别或远端集成，不保证忘记关闭后 vim／opencode 的输出不被着色。新建、重连及重启恢复终端默认关闭，切换标签保留当前终端开关。
- 规格检查：补齐终端自带右键菜单保留、首字节刷新期限、未完成控制内容的有界透传、空模式／零宽匹配／单词边界及规则编辑快照约束，未改变 Q22 的功能形态。
- 后续范围调整：用户明确不再需要单独的 JSON 高亮，关键字／正则即可覆盖所需功能；移除 JSON 预设、语法解析及独立任务，JSON 内容仅按普通文本匹配。
- 用户已确认[四项实施计划](plan.md)，并已发布独立本地任务：依赖为 01 → 02 → 03，04 缓冲档位独立；每项均包含端到端验证。
- 04 已完成并合入：四档缓冲设置在新建／重连尝试开始时捕获，保存不改变已有或连接中的终端。包测试与原生专项覆盖取消、写入冲突、迁移、重启、窄窗口及 2／8 MiB 历史淘汰差异，见[任务结论](issues/04-scrollback-settings.md#answer)；各档正式资源比较留待综合验收。
