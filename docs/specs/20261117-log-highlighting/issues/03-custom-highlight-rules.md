# 03：配置自定义关键字与正则规则

## What to build

用户在设置中新增、编辑、删除、启停及调整自定义规则顺序，通过关键字或正则和选定颜色突出业务内容，包括 JSON 日志中的字段名或业务值。规则全局保存，仍由每个终端独立开启高亮；不提供专门 JSON 解析或分类功能。

## Acceptance criteria

- [ ] 设置支持普通关键字／正则类型、匹配内容、颜色、逐条启停、增删编辑及上下调整顺序，保留键盘和窄窗口可用性；每条自定义规则使用一种用户选定的颜色。
- [ ] 普通关键字按原文片段匹配，可切换大小写敏感；正则采用 Go 语法，不支持回溯引用与前后查找，保存前清楚提示无效表达式。空关键字／空正则、无效颜色及超出预算的配置在保存／导入前拒绝，零宽匹配忽略且不插入颜色。
- [ ] 服务器显式 ANSI 前景色优先；自定义规则按列表从上到下优先，其次内置日志级别、日期。重叠命中只按既定优先级着色，以局部重叠及大小写样本固定结果。
- [ ] 规则内容、类型、开关、顺序、大小写选项和颜色随本地保存、重启及配置迁移完整保留；编辑取消、写入失败和校验失败不改变生效配置或部分覆盖旧规则。
- [ ] 保存成功仅更新已启用终端后续处理的输出，历史颜色和每终端开关保持不变；后台不共享 UI 的可变编辑列表。
- [ ] 分块及超时后已显示边界允许漏色但不丢字；规则数、模式长度、单次处理内容、匹配结果及输出扩张有经验证的预算。超长内容／大量匹配仅有界降级高亮并提示，不阻塞终端，不增加无限等待或整行缓存。
- [ ] JSON 日志仅作为普通文本匹配样本：可用规则突出字段名或业务值，不识别对象边界、嵌套、键值类型或有效性，不为此等待结构完整。
- [ ] 覆盖校验、规则优先级、任意分块、超限降级、保存失败、取消及迁移回归；在本地临时 SSH 原生窗口演示规则增删和重排前后的新增日志，复核独立终端开关、搜索、原文复制及已有 ANSI 样式。
