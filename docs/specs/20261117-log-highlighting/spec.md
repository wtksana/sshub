# 终端日志高亮与历史缓冲设置

状态：2026-11-18 已完成四项功能、回归、原生专项、双轴审查及默认 2 MiB 的正式十分钟高亮开／关负载。用户通过 Q22 确认操作形态、取消专门 JSON 高亮，并在正式采样后取消 8／32／64 MiB 资源对比；按最新范围完成交付。见[验证记录](../../verification/20261117-log-highlighting.md)与[实施计划](plan.md)。讨论过程与被替代的方案见[需求地图](map.md)。

## 目标与操作

用户继续在现有 SSH 终端中使用 `tail` 等命令。在终端右键菜单中开启／关闭“日志高亮”，只控制该终端；设置中编辑全局共用的规则。

- 默认关闭。新建、重连、重启恢复的终端均关闭，不持久保存开关；切换标签保留当前会话的开关。
- 右键菜单保留原有复制、粘贴、全选和清屏能力，开关显示当前状态并支持键盘访问；不依赖父级菜单能穿透终端自带菜单。
- 开启期间，该终端新增输出按规则着色，不判断当前命令。其他终端不受影响。
- 看日志后由用户关闭。若未关闭，后续普通命令或交互程序也可能被着色；不承诺自动识别或排除 vim、opencode。
- 开启前的文本不补色；改规则、切换主题或关闭高亮不改变已显示内容的颜色。配置变更只影响之后处理的输出，已在处理中的片段可沿用旧配置。
- 保留文字、顺序、换行与复制内容。搜索及选中内容保持可辨识。

## 规则

规则在本机持久保存，所有终端共用，支持逐条启停、颜色调整、自定义规则增删及顺序调整。

| 类型 | 首版行为 |
| --- | --- |
| 日志级别 | TRACE、DEBUG、INFO、WARN／WARNING、ERROR、FATAL／PANIC，按完整单词匹配且忽略大小写 |
| 日期／时间 | 常见 YYYY-MM-DD、YYYY/MM/DD、时间及 ISO 8601 组合；其他格式通过自定义规则补充 |
| 普通关键字 | 按原文片段匹配，可切换大小写敏感 |
| 正则 | Go 正则语法，不支持回溯引用与前后查找；保存前提示无效表达式 |

服务器已有显式 ANSI 前景色优先，只对默认前景色补充高亮。自定义规则按列表从上到下优先，其次日志级别、日期。

JSON 内容按普通文本参与关键字／正则匹配，不提供 JSON 解析、语法分类或专门预设。例如用户可用规则突出字段名或业务值，不要求识别对象／数组的起止、嵌套及完整性。

内置配色适配浅／深主题；每条自定义规则首版使用用户选定的一种颜色。规则调整仅影响各已启用终端的新增输出。规则或偏好读取、保存、导入校验沿用现有配置约束，不静默覆盖损坏数据或外部修改。

空关键字、空正则、无效颜色或超出规则预算的配置在保存／导入前拒绝，不能先应用部分配置。正则产生的零宽匹配忽略，不插入颜色；“完整单词”的首版边界按 ASCII 字母、数字、下划线区分，并用例固定 `error` 与 `errors` 的差异。规则列表编辑和取消不修改当前生效规则；保存成功后再发布给后台读取方，已有会话不会读到半更新的列表。

## 流式输出边界

在 SSHub 本地转换新增输出，使用现有 MyGo 与 Ghostty，不维护依赖补丁，不升级依赖，不安装远端工具或加载 shell 集成。不记录用户输入，不推测命令开始或结束。

- 以最多约 20 ms 的额外等待为原型目标，从首个尚未转发的普通文本字节计时，持续到达的新数据不能反复推迟刷新；即使底层下一次读取尚未返回，也要能刷新已经收到的提示符。不能等待换行才显示。微基准开启时 p50 20.402 ms、p95 20.775 ms、最大 25.931 ms，包含调度，不是严格 20 ms 保证或屏幕呈现延迟。
- 超时后先显示；跨越已显示边界的关键字／正则允许漏色，不回写历史。不为 JSON 或其他内容等待结构完整。
- UTF-8 和控制序列可在任意网络分块处截断，不能在未完成的编码或控制序列中插入颜色。
- 等待时间和保留内容都有上限；未完成或未知的控制内容达到预算时转为不插色的原样透传，不能因等不到终止符无限增长缓存。高亮关闭时仍保守跟踪必要的控制状态，避免开启时将原有颜色或控制串中段误当作普通文本。
- 保留原有前景色、背景及其他样式；不能以清除全部样式代替结束新增颜色。
- 常见备用屏幕切换可作为暂停着色的保护，但不依赖它识别命令。不能可靠处理的复杂控制内容原样透传，跳过相应高亮，不重写光标行为。
- 超长行或处理超出预算时只降级高亮并给出提示，不丢弃文字。具体长度、规则数量及输出扩张预算通过实现验证确定，避免提示刷屏。
- 关闭或改规则时安全结束当前插入的颜色，后续文本不继承错误样式。断开、取消、EOF 和带数据的错误不能丢失已接收的尾部内容。

## 历史缓冲

现有每终端设置为约 2 MiB 的历史回滚预算，没有累计输出行数上限。持续输出淘汰最旧历史，实际可回看行数受终端宽度、折行、文字及样式影响。

设置新增 2／8／32／64 MiB 档位，默认 2 MiB，持久保存；仅对新建或重连终端生效，现有终端保持创建时的档位。缓冲预算不等于同量的进程内存，不承诺固定保留行数，也不恢复被淘汰内容。

## 验证计划

先验证本地流式转换，再接入设置和终端菜单；如果关键兼容性无法满足，记录证据后重新讨论，不退回依赖补丁或远端配置修改。

1. 流式回归：跨分块关键字／正则匹配／中文、超时提示符、原有 ANSI 样式、截断及未知控制序列、超长内容降级、EOF／取消与配置切换；验证去除新增颜色后文字及原始控制内容不变。含 JSON 的日志仅验证普通规则匹配及文字保留，不验证语法着色。
2. 会话隔离：两个终端独立开关；切换标签保留，重连关闭；输入、Resize、Close 及共享 SSH／SFTP 生命周期保持可用，诊断统计仍按原始接收量计数。
3. 配置回归：旧配置默认值、规则顺序／无效正则、保存失败、导入导出及缓冲新会话生效。
4. 原生窗口：右键菜单和设置、tail 连续输出、中文软折行、搜索、选择复制、原有颜色、普通提示符与常见备用屏幕进入／退出。检查忘记关闭高亮的边界，不将其描述为自动排除全屏程序。
5. 正式构建在默认 2 MiB 下对比关闭／开启高亮的负载及内存趋势；沿用八会话各 1,000 条逻辑行／秒、十分钟场景作为对比负载，记录环境、规则数、行长、日志样本、可见窗格及预算。用户于 2026-11-18 取消 8／32／64 MiB 资源比较。额外拼片等待由流转换微基准记录；接收速率不视为渲染吞吐，端到端延迟与最高渲染吞吐未测量。

代码检查按实际影响范围执行 test／vet、MyGo 原生标签与专项窗口验证。执行结果见[交付验证](../../verification/20261117-log-highlighting.md)与[本次正式负载报告](../../performance/20261118-log-highlighting.md)，历史报告不代替本次结果。
