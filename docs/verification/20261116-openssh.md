原始证据：`artifacts/openssh-ui/20261116-214817/`。无秘密结果另存为 [openssh-summary.json](20261116-openssh-summary.json)。

- 产品确认框显示的主机指纹与 `ssh-keygen -l` 从临时主机公钥计算的值一致，核对后才接受；新用户私钥完成真实 OpenSSH 认证。
- Windows PTY shell 回显通过。先设置临时环境变量，再由下一命令拼接输出标记，产品搜索仅匹配一处，避免把本地命令行回显当作服务器执行证据。

## 复现与环境条件

解压上述 OpenSSH ZIP，准备同一用户权限下可用的 Vim，在仓库 PowerShell 7 中执行：

```powershell
./scripts/verify-openssh-ui.ps1 -OpenSSHDirectory <解压后的OpenSSH-Win64目录>
# 已有对应调试构建时可加 -SkipBuild -BuildDirectory build/p6
# 非默认 Vim 位置可加 -Vim <vim.exe的路径>
```

脚本创建临时配置、密钥与数据，仅允许当前用户名认证，并为生成的 `authorized_keys` 设置当前用户、SYSTEM 与 Administrators 的 ACL；保持 `StrictModes yes`。所有运行文件都位于忽略的 `artifacts/`，不修改系统账户或全局 OpenSSH 配置。

便携 sshd 使用显式路径的 `sftp-server.exe` 子系统。本机尝试 `internal-sftp -d ...` 时通道提前 EOF；改为发行包中的外部子系统后产品浏览／新建目录通过。不能将此测试环境配置问题归为产品协议缺陷。

SFTP 的 `-d` 只设置起始目录，不提供 chroot 隔离；脚本只操作自己生成的测试文件。此次 Windows OpenSSH／Vim 验证不代表 Linux OpenSSH、Unix 权限位、Linux top、中文输入法组合、系统 Agent 服务、系统拖放或长时间 Vim 使用均已验收。字面中文输入也不等于输入法组合输入。
