## 已补齐：Windows 文件与文件夹拖入

用户已实际从资源管理器拖入并确认完成；两个任务均成功，中文文件与嵌套文件哈希一致、空目录保留，见[拖入专项](20261116-native-drop.md)。此项从剩余列表移除；以下步骤保留供复测。

需要实际鼠标从资源管理器拖到产品窗口。当前 computer-use 拖动 API 拒绝终点超出源窗口边界，因此需要人工执行这个手势。

1. 在交互 PowerShell 7 终端执行 `./scripts/verify-sftp-ui.ps1 -SkipBuild -BuildDirectory build/p6 -TransferPickers`，等文件管理验证通过并暂停。
2. 在另一终端执行 `./scripts/verify-native-drop.ps1 -PrepareOnly`。脚本准备随机内容的中文文件、嵌套文件夹及空目录，打印目录；不执行上传。
3. 在资源管理器打开打印的 `native-drop-source`，产品右侧路径保持 `/`。同时选中文件“拖入 中文.txt”和“拖入 文件夹”，真正拖到右侧文件列表中，等待队列任务成功。记录实际手势及任务结果。
4. 执行 `./scripts/verify-native-drop.ps1 -CheckOnly`，核对远端逐文件 SHA256、嵌套及空目录。文件到达不能单独证明使用了系统拖放；必须与第 3 步实际观察配对。
5. 回到第一个终端按回车，脚本正常退出产品并清理临时服务器。证据保存在该次 `artifacts/sftp-ui/<日期时间>/`。

如果拖动显示禁止图标，先记录资源管理器与 SSHub 是否以相同权限级别运行；不要通过关闭 UAC 或修改安全设置解决。产品终端区域的文件拖入不是右侧 SFTP 上传场景。

## 重启冷启动

须在用户安排重启之后测量；不由 agent 直接重启电脑。重启前将候选包、100 配置测试目录和记录位置准备好，重启后在第一次运行 SSHub 时记录：Windows 版本、启动时间、EXE SHA256、进程启动时间、首帧显示时间，以及真实操作结果。
