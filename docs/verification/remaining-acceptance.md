# 首版剩余人工与环境验收

当前 P6 保持进行中；以下操作尚未完成，不以准备脚本或相邻测试通过代替结果。已通过项目见[逐项验收](../specs/20261116-sshub-v1/acceptance.md)。测试使用临时配置与生成文件，不操作用户服务器。

## Windows 文件与文件夹拖入

需要实际鼠标从资源管理器拖到产品窗口。当前 computer-use 拖动 API 拒绝终点超出源窗口边界，因此需要人工执行这个手势。

1. 在交互 PowerShell 7 终端执行 `./scripts/verify-sftp-ui.ps1 -SkipBuild -BuildDirectory build/p6 -TransferPickers`，等文件管理验证通过并暂停。
2. 在另一终端执行 `./scripts/verify-native-drop.ps1 -PrepareOnly`。脚本准备随机内容的中文文件、嵌套文件夹及空目录，打印目录；不执行上传。
3. 在资源管理器打开打印的 `native-drop-source`，产品右侧路径保持 `/`。同时选中文件“拖入 中文.txt”和“拖入 文件夹”，真正拖到右侧文件列表中，等待队列任务成功。记录实际手势及任务结果。
4. 执行 `./scripts/verify-native-drop.ps1 -CheckOnly`，核对远端逐文件 SHA256、嵌套及空目录。文件到达不能单独证明使用了系统拖放；必须与第 3 步实际观察配对。
5. 回到第一个终端按回车，脚本正常退出产品并清理临时服务器。证据保存在该次 `artifacts/sftp-ui/<日期时间>/`。

如果拖动显示禁止图标，先记录资源管理器与 SSHub 是否以相同权限级别运行；不要通过关闭 UAC 或修改安全设置解决。产品终端区域的文件拖入不是右侧 SFTP 上传场景。

## 真实 Windows OpenSSH Agent 服务

当前系统 `ssh-agent` 为 `Stopped / Disabled`；本次未更改。现有命名管道测试覆盖真实签名协议，不等同于微软服务实测。

需要由用户准备可用且已载入测试密钥的系统 Agent 环境。不得清空已有密钥。使用隔离回环 SSH 服务器，只添加本次临时密钥，核对 `ssh-add -l` 指纹，再以产品“Windows OpenSSH Agent”方式连接并正常核对服务器身份。验证后仅移除本次新增密钥，保留原有密钥。记录 Agent 版本、服务状态、临时密钥指纹、连接／SFTP／退出结果；不把私钥或签名载入公开报告。

如需启用／停止或变更服务启动方式，先取得用户对具体操作的同意，保留原设置并在完成后恢复。尚未实际执行该场景。

已准备 `verify-system-agent-ui.ps1 -OpenSSHDirectory <OpenSSH-Win64目录>`：要求服务已运行，自身不变更服务设置；只添加新生成的测试密钥，使用产品默认系统管道验证签名、SFTP 中文列表、终端回显与正常退出，finally 仅移除该临时公钥并核对原有指纹集合恢复。现阶段只验证服务停止时脚本会在任何副作用前拒绝；真实服务成功路径仍待授权后执行。脚本要求已有 `build/p6` 调试程序及两个 build/tools 测试工具。

## 重启冷启动

须在用户安排重启之后测量；不由 agent 直接重启电脑。重启前将候选包、100 配置测试目录和记录位置准备好，重启后在第一次运行 SSHub 时记录：Windows 版本、启动时间、EXE SHA256、进程启动时间、首帧显示时间，以及真实操作结果。

`measure-startup.ps1 -Repeats 1` 可测首次进程首帧，但脚本会自己创建 100 配置，且“重启后第一次运行”需要现场确认。可操作性另用 `measure-startup-interaction.ps1 -Repeats 1` 与真实键盘／截图配对；两个脚本不能各自声称是同一次重启后的首次运行。若只获得首帧，应明确冷启动可操作性未计量。当前缓存启动已通过，不套用它作为冷启动结果。

## 全新 Windows 运行环境

需要已有或由用户准备的全新 Windows x64 测试机／虚拟机；宿主有 Go，仅限制 PATH 的测试不能证明环境干净。将完整候选 ZIP 和包外 SHA256SUMS 复制过去，核对下载来源／包哈希，解压后双击 EXE，正常退出，再运行包内 `verify-portable-runtime.ps1`。

该脚本兼容系统自带 PowerShell 5.1，不需要 Go、Node、Python 或 PowerShell 7，核对文件哈希、临时配置启动、正常退出、更换程序目录及配置／主题／信任／布局保留。执行方式见[便携说明](../portable-readme.md)。证据保存在脚本输出的临时目录；如运行策略禁止文件脚本，说明中提供直接执行代码的方式，不改变策略。

记录测试系统镜像／安装来源、系统版本、已安装开发工具情况和实际操作；脚本中“可发现工具”清单只能辅助说明。还需连接隔离服务器打开终端，确认中文输出及 Ghostty DLL 实际加载。全新 Linux 服务器虚拟机不能代替全新 Windows 客户端环境。
