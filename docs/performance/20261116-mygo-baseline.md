# MyGo 最小原型性能基线

历史记录：对应原型代码及专用脚本已按用户要求移除，文中命令仅描述当时的测量方法，不是当前项目的运行入口；数据不代表当前产品版性能。

测量日期：2026-11-16，Asia/Hong_Kong。结论：原生终端原型已可运行，启动较快；内存应按约 80–180 MiB 的实测量级规划，不能沿用 hello-world 宣传数字。当前不足以证明它优于其他框架，也未验证真实网络和文件传输吞吐。

## 环境与构建

- Windows 11，系统版本 10.0.26300.0；Intel Core Ultra X7 358H，16 个逻辑处理器，31.55 GiB RAM。
- Go 1.27.4、MyGo v0.9.1、官方固定版本 libghostty-vt；正式构建关闭 inspector，使用 `mygo_nowebview`。
- 1180×760 DIP 窗口；本机截图实际内容为 1748×1084 物理像素，字体 Cascadia Mono 13 DIP；每终端 2 MiB 历史缓冲。
- EXE 13.83 MiB，Ghostty DLL 2.07 MiB，合计约 15.91 MiB。直接运行 EXE 时需保留旁边的 DLL。
- 正式构建 SHA-256：`B8532F6633A8461FA73CCA1659DA16C8944DEF653FD5B8F681EAF9014EF1D628`。
- 回放在同一个进程生成，包含 ANSI 颜色、中文、英文和换行；没有 SSH 网络或 shell 子进程。每终端目标 1000 条逻辑行/秒，分屏时长行会折行，所有终端同时可见。

## 12 秒、每种场景重复三次

每次创建新进程，首帧之后第 3 秒开始负载，第 12 秒自动退出。操作系统每 250 ms 采样；稳态统计取进程创建 4 秒后的样本。下表是三个试次各自指标的中位数，原始每次结果见 [summary.csv](20261116-baseline/summary.csv)。

| 场景 | 进程创建至首帧 | 工作集 | 私有提交量 | CPU（单核=100%） | 终端输入速率 |
|---|---:|---:|---:|---:|---:|
| 单终端空闲 | 243 ms | 78.6 MiB | 98.0 MiB | 0.96% | — |
| 单终端持续输出 | 222 ms | 107.2 MiB | 124.6 MiB | 18.7% | 0.096 MiB/s |
| 4 终端持续输出 | 225 ms | 110.3 MiB | 128.0 MiB | 26.2% | 0.385 MiB/s |
| 8 终端持续输出 | 231 ms | 128.5 MiB | 141.0 MiB | 49.0% | 0.770 MiB/s |

十二次启动全范围为约 220–307 ms。8 终端各试次工作集指标为 115.2、128.5、141.8 MiB，CPU 为单核 30.5%、49.0%、49.4%，有明显波动。不能将 12 秒的结果当成长时间内存上限。

最早的冒烟版本首次启动测得约 728 ms，后续为 224–239 ms；它与正式基线的字体配置/构建哈希不同，故未混入上述统计，也不据此给出重启冷启动结论。

## 8 终端追加 60 秒

同一正式 EXE、相同速率和历史缓冲，首帧后运行 60 秒，其中约 57 秒持续输出。共接收约 43.94 MiB 数据，平均终端输入速率约 0.771 MiB/s；CPU 稳态均值为单核 38.0%，折算 16 核整机约 2.38%。

| 进程启动后的时间段 | 平均工作集 | 平均私有提交量 |
|---|---:|---:|
| 4–14 秒 | 116.2 MiB | 134.5 MiB |
| 14–24 秒 | 139.9 MiB | 158.1 MiB |
| 24–34 秒 | 160.9 MiB | 179.1 MiB |
| 34–44 秒 | 166.0 MiB | 183.9 MiB |
| 44–54 秒 | 176.8 MiB | 190.9 MiB |
| 54 秒至结束 | 181.0 MiB | 193.4 MiB |

最后几个采样点的工作集约 181.0 MiB；单次 60 秒内的末段近似持平，不能据此证明长期完全稳定，也不能仅凭增长判定泄漏。历史缓冲、缓存及运行时需要进一步拆分验证。Go 退出时记录的 HeapAlloc 约 44.3 MiB，它并不等于整个进程工作集。

原始 [60 秒汇总](20261116-baseline/long-summary.csv)、[逐次采样](20261116-baseline/long-samples.csv)、[环境与文件哈希](20261116-baseline/long-environment.json) 已保留。

## 已完成的功能验证

- `go test ./...`、`go vet ./...` 通过。
- 临时回环 SSH/SFTP 服务器验证：密钥认证、UTF-8 shell 收发、远端窗口尺寸、SFTP 目录读取、拒绝未知与变化的主机密钥。
- 回放连接验证：空闲 UTF-8 回显、关闭解除回压阻塞。
- 官方 automation 插件验证四个可见终端、开始/暂停、输出期间中文输入框更新与退出；截图显示四个终端实际输出。该检查验证操作结果，没有量化按键到屏幕的延迟，也没有验证真实输入法候选窗口。
- 正式版本地 shell 冒烟检查通过：能启动 pwsh/ConPTY、绘制窗口、按时退出并清理子进程。此模式的内存和 CPU 未纳入上表。
- `git diff --check` 和 UTF-8 无 BOM 检查通过。

## 测量局限

- 每次新进程但保留系统文件/驱动缓存；不是重启冷启动，也不是受控的跨框架对比。
- 首帧使用 MyGo `OnReadyToShow`（首帧绘制完成）时间，非硬件呈现时间、可交互延迟或 SSH 提示符出现时间。
- 工作集为驻留物理页，私有提交量是另一种内存口径，不能相加；GPU 专用/共享内存未单独测量。
- CPU 包含本进程的输出生成器；100% 指一个逻辑核。机器上其他任务和电源/频率变化未受控。
- 输入字节数不代表渲染吞吐或帧率。Go UI build 计时不包括布局/GPU，部分读数低于时钟分辨率，未用其声称 60/120 FPS。
- 未测真实服务器、大文件/小文件 SFTP 传输、vim/tmux、复杂输入法、休眠重连、小时级运行或其他操作系统。

## 复现

在项目根目录的 PowerShell 7：

```powershell
./scripts/benchmark.ps1 -Repeats 3 -Seconds 12
./scripts/benchmark.ps1 -SkipBuild -Scenario load-8 -Repeats 1 -Seconds 60
./scripts/verify-ui.ps1
```

UI 检查会改为调试构建；之后运行 `./scripts/build.ps1` 恢复正式构建再测性能。原始完整 JSON/CSV 在 `artifacts/benchmarks/`，对应代码和测量说明见根目录 README。
