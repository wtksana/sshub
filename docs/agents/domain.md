# 领域文档

## 布局

采用 single-context：

- 根目录 `GLOSSARY.md`：领域术语。
- `docs/adr/`：架构决策记录。

## 阅读规则

- 探索代码前读取已有术语表，以及与当前工作相关的 ADR。
- 文档不存在时直接继续，不提示缺失，也不预先创建空文件。
- 术语或决策明确后，由 domain-modeling 技能按需创建文档。
- 如果以后出现 GLOSSARY-MAP.md，按其指引读取相关上下文。

## 使用规则

- Issue、设计、诊断和测试命名使用术语表定义的词汇。
- 缺少术语时先判断是否确有需要，再记录为领域建模事项。
- 建议与现有 ADR 冲突时，明确指出冲突及重新讨论的理由。
